# GAAP delivery and decision checklist

GAAP governs one bounded Agent Run and its protected effects. A maintainer can use this checklist to find the evidence for each remaining issue, see who owns the next decision and tell which work can proceed. The inventory starts at `f9d4d99d00c04ecafb6f916635d37ad0cf146c11` on November 21, 2026. At that revision GitHub listed five open issues, zero open PRs and zero milestones. The accepted ADRs, implementation plans and completed child issues supply evidence for those five issues. Example approval forms and ideas without an owning decision don't add implementation work. ## Recovery decision and ordered follow-ups

The accepted design covers one private workspace on one host, cooperating writers and one synchronous local replacement. Restart reads durable facts. If the host stopped after dispatch, two identical journals can correspond to zero or one actual writes. A qualified witness can establish an effect outcome. An unresolved effect holds the workspace. Approval continuation is deferred. A new attempt needs fresh identities, authority, budget and subject checks. The original terminal receipt stays sealed. [ADR 0009](../adr/0009-durable-agent-run-reconciliation.md)

## Benchmark and explorer gates

For #7 the five proposed tasks exercise repeated pre-PR repair, review rejection, local provisioning failure, an unresolvable task and stale evidence across ordered commits. Corpus acceptance needs offline observable transitions, public/verifier-only checks, controlled decoys and gold patches where applicable. The unsolvable task has its own validation rule. Resolve how a review-only constraint can pass functional tests while the validator detects its decoy, and how to prove a task really requires multiple cycles. The opt-in experiment follows a validated second corpus and explicit adoption. Freeze ThreadLoop identity and measures before any run. The proposed one-repetition design has 5 tasks × 2 providers × 6 conditions × 2 lifecycle settings = 120 sequential trials. A maintainer must choose count and cost before implementation. Retain all protections for host, isolation and spend. Predeclare verifier pass rate, cycles, wasted commits, cost per resolution and unsafe transitions. One run per cell supports descriptive reporting only. [Issue #7 and corpus specification](https://github.com/nnennandukwe/governed-agent-autonomy-patterns/issues/7#issuecomment-5142647222)

For #1 an executable isolated harness, a frozen task/failure/configuration/prompt/tool/retry/sample plan, comparable governed and separately ablated runs, raw receipts and reproducible aggregates, provider-native cost reconciliation, scoped claims and human review must all precede an explorer. The archive's example needs real image digests and a price snapshot valid at freeze time. The [historical pilot work](https://github.com/nnennandukwe/governed-agent-autonomy-patterns/pull/5) reports corpus and deterministic checks. It supplies no basis for a comparative outcome claim. #1 can use qualifying single-axis data independently of #7.

After acceptance, every number must resolve to a versioned packet, each comparison must name its disabled gate, filters must show their denominators, and failed, excluded and incomplete runs must remain visible. Include run receipts, uncertainty, retries, protocol/fixture/harness/result digests, packet download, claim limits and public reproduction. Verify accessibility, mobile layout and the static fallback. [Explorer evidence and acceptance criteria](https://github.com/nnennandukwe/governed-agent-autonomy-patterns/issues/1)
